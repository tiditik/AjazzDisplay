# AJAZZ Screen — загрузка картинок и GIF на экран мыши без UI

Скрипт отправляет изображение или анимацию на экран мыши AJAZZ напрямую через
gRPC-мост официального драйвера. Окно AJAZZ Driver при этом можно не открывать —
достаточно, чтобы драйвер был запущен (он держит HID-устройство и слушает
`127.0.0.1:3814`).

```
node upload.js photo.png
node upload.js animation.gif
node upload.js photo.jpg --fit cover
node clock.js            # часы на экране мыши
```

> Неофициальный проект, не связан с AJAZZ. Использует внутренний интерфейс
> драйвера, который может измениться в новых версиях. Всё — на ваш риск.

## Требования

* Windows.
* Установленный и **запущенный** AJAZZ Driver (он поднимает `iot_driver_v190.exe`,
  который и общается с мышью по HID).
* Мышь подключена; для записи картинки надёжнее проводной режим (само приложение
  предупреждает, что в 2.4G запись картинок отключена).
* Node.js 18+.

Установка зависимостей:

```
npm install
```

## Использование

```
node upload.js <файл> [опции]
```

| Опция | Значение |
|---|---|
| `--fit contain\|cover\|stretch` | как вписать картинку в квадрат 128×128 (по умолчанию `contain` — целиком, с чёрными полями) |
| `--size N` | размер экрана, по умолчанию `128` |
| `--device SUBSTR` | выбрать HID-интерфейс по подстроке пути (по умолчанию `MI_02`) |
| `--delay MS` | пауза между пакетами, по умолчанию `6` мс. **Меньше — нельзя: устройство теряет данные** |
| `--repeat N` | отправить каждый пакет N раз (по умолчанию `1`) |
| `--passes N` | отправить весь кадр N раз (по умолчанию `1`) |
| `--max-frames N` | максимум кадров GIF, 1…255 (по умолчанию `255`); лишние кадры прореживаются, задержки суммируются |
| `--strict` | вместо прореживания завершиться с ошибкой, если в GIF больше кадров, чем разрешено |
| `--raw FILE` | отправить готовый буфер `128*128*2` байт |
| `--list` | только показать найденные HID-интерфейсы |
| `--dry-run` | подготовить кадр, но ничего не отправлять |

Примеры:

```
node upload.js cat.png                 # PNG/JPG/BMP, вписать целиком
node upload.js cat.png --fit cover     # заполнить экран с обрезкой краёв
node upload.js anim.gif                # GIF-анимация (все кадры)
node upload.js --list                  # какие HID-пути видит драйвер
```

Скорость: статичная картинка — около 4 секунд (586 пакетов × 6 мс), GIF — примерно
4 секунды на кадр.

## Часы

```
node clock.js                  # 24-часовой формат, обновление раз в минуту
node clock.js --12h            # 12-часовой формат
node clock.js --once           # отправить текущее время один раз и выйти
node clock.js --preview a.png  # только нарисовать картинку, устройство не трогать
```

Передача кадра занимает около 4 секунд, поэтому картинка со следующей минутой
отправляется заранее (`--lead MS`, по умолчанию 4500 мс), и экран меняется
примерно в момент смены минуты. Секунды показать нельзя — слишком медленная запись.

Чтобы выводить на экран что-то своё (погоду, загрузку CPU, курс), достаточно
нарисовать картинку 128×128 через Jimp и передать её в `uploadImage` из
`screen.js`.

## Использование как библиотеки

```js
const { DriverClient, listDevicePaths, pickDevicePath } = require('./ajazz');
const { uploadImage } = require('./screen');
const { imageToFrame } = require('./image');

const client = new DriverClient();
const path = pickDevicePath(await listDevicePaths(client));
await uploadImage(client, path, await imageToFrame('photo.png'));
client.close();
```

## Как это устроено

AJAZZ Driver — это Electron-приложение, но сама работа с устройством вынесена в
отдельный Rust-процесс `iot_driver_v190.exe` (`tonic` + `tonic-web`). Приложение
общается с ним по gRPC-Web на `http://127.0.0.1:3814`, сервис
`driver.DriverGrpc`. Скрипт говорит с тем же сервисом обычным gRPC поверх HTTP/2
(встроенный модуль Node `http2`, без сторонних библиотек).

Используются методы:

* `watchDevList` — список HID-интерфейсов (нужен путь вида
  `\\?\HID#VID_3151&PID_5007&MI_02#...`);
* `setLightType` — переключить режим подсветки/экрана (`OTHER`, чтобы остановить
  стриминг экрана перед записью);
* `sendRawFeature` — записать HID feature-report (по сути, «пакет»);
* `readRawFeature` — прочитать ответ устройства.

### Формат кадра

Экран — 128×128, 16 бит на пиксель, **RGB565 big-endian**. Прошивка сканирует
панель повёрнутой, поэтому картинка перед отправкой **транспонируется**
(строка кадра = столбец исходника). Это ровно то, что делает официальное
приложение.

### Обмен

1. `setLightType(OTHER)` — остановить экранный режим.
2. Рукопожатие 18 байт, команда `0xA5`:
   `A5 00 01 00 <длина LE32> <left> <top> <right> <bottom> <старшие байты...>`.
   Затем `readRawFeature`; ответ с `msg[1] == 1` означает готовность.
3. Данные: 586 пакетов по 56 байт. Заголовок 8 байт:
   `25 <frameIndex> <frameCount> <frameDelay> <chunkIndex LE16> <chunkLen> 00`,
   дальше 56 байт пикселей (последний пакет короче).
4. Финал: команда `0xF1` + чтение (как в приложении).

Для анимации рукопожатие делается один раз с `frameCount = N` и задержкой первого
кадра, затем каждый кадр шлётся со своим `frameIndex` и `frameDelay` (в
миллисекундах, 20…255; GIF-задержка берётся как `delay_cs * 10`).

### Почему пауза 6 мс

Драйвер отвечает на gRPC примерно за 1 мс, но фактическая запись в HID идёт
асинхронно. Если слать быстрее, часть пакетов теряется и на экране появляется
«мусор» (обычно полосой слева). Официальное приложение выдерживает ~6,5 мс на
пакет; значение 6 мс воспроизводит это поведение.

## Файлы

| Файл | Назначение |
|---|---|
| `upload.js` | CLI: разбор аргументов, отправка картинки/анимации |
| `clock.js` | часы на экране мыши |
| `screen.js` | отправка кадра/анимации на устройство (рукопожатие, пакеты, финал) |
| `ajazz.js` | gRPC-клиент, protobuf-кодирование, протокол экрана |
| `image.js` | декодирование картинки, RGB565, транспонирование |
| `gif.js` | разбор GIF на кадры с учётом disposal |

## Ограничения

* Работает только при запущенном AJAZZ Driver: скрипт не открывает HID сам,
  а использует мост драйвера.
* Рассчитано на экран 128×128 (модель из устройства `VID_3151&PID_5007`).
  Для других моделей размер и HID-путь можно задать через `--size` и `--device`.
* Задержки GIF ограничены 20…255 мс, число кадров — 255 (номер кадра занимает 1 байт).
* Скрипт не сохраняет картинку в локальную БД приложения, поэтому в самом
  приложении она не появится (на устройстве — появится).
